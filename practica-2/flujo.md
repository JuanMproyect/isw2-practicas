# Practica 2 - Diferencia entre GitFlow y trunk-based

La diferencia entre GitFlow y trunk-based depende de la metodología de desarrollo del equipo y del objetivo del proyecto. GitFlow es un modelo de ramas con estructura fija, tiene una rama main para producción, una rama develop para integrar el trabajo, ramas feature para cada funcionalidad, ramas release para preparar versiones y ramas hotfix para corregir errores urgentes. Está pensado para software con versiones numeradas y lanzamientos planificados, donde a veces hay que mantener varias versiones en producción al mismo tiempo. Las ramas pueden vivir días o semanas, y el despliegue es un evento controlado, no algo continuo.

Trunk-based en cambio, se basa en que todo el equipo integra sus cambios en una sola rama principal mediante ramas muy cortas, de horas o uno o dos días como máximo. Su característica principal no es usar Git, ramas o pull requests, porque eso también se hace en GitFlow, sino la integración continua y frecuente. Para que funcione bien se apoya en pruebas automáticas, CI/CD y feature flags, que permiten ocultar funciones sin terminar mientras el código ya está integrado. Esto reduce los conflictos de merge, permite detectar errores más rápido y facilita desplegar cambios constantemente.

Para desarrollar una app web yo usaría trunk-based, porque una app web normalmente tiene una sola versión en producción que controla el propio equipo, así que no hace falta la complejidad de las ramas develop y release de Git Flow. Además, me permite trabajar en equipo de forma fluida y mantener el proyecto actualizado en todo momento, siempre que se cuente con pruebas automáticas y un buen pipeline de CI/CD que den seguridad al integrar cambios con frecuencia.
